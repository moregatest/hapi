# HAPI 項目安全審計報告

## 項目概述
HAPI 是一個本地優先的 AI 編程會話管理工具，允許通過 Web 界面、PWA 或 Telegram Mini App 遠程控制和監控 Claude Code/Codex/Gemini 會話。

## 安全評級：**中等風險** ⚠️

---

## ✅ **安全優點**

### 1. **密鑰管理**
- **無硬編碼密鑰**：所有敏感信息通過環境變量管理
- **強密鑰生成**：使用 `crypto.randomBytes(32)` 生成 256 位安全令牌
- **弱密鑰檢測**：自動檢測並警告弱的用戶提供令牌
- **正確的 .gitignore**：排除 `.env` 文件和敏感數據

### 2. **身份驗證機制**
- **雙因子認證**：支持 CLI_API_TOKEN 和 Telegram initData 驗證
- **JWT 實施**：使用 Jose 庫，15分鐘過期時間
- **時間安全比較**：Telegram 簽名驗證使用 `timingSafeEqual`
- **請求頭和查詢參數**：支持 Bearer token 和查詢字符串認證

### 3. **輸入驗證**
- **Zod 架構驗證**：所有 API 輸入使用類型安全驗證
- **路徑安全檢查**：防止目錄遍歷攻擊
- **參數淨化**：正確處理文件路徑和用戶輸入

### 4. **進程執行安全**
- **參數化執行**：使用 `execFile` 而非 `exec` 執行 git 命令
- **受控環境**：子進程使用受限環境變量
- **超時保護**：防止長時間運行的命令

## ⚠️ **安全問題**

### 1. **依賴漏洞** - 中等風險
```
esbuild <=0.24.2 - 開發服務器 SSRF 漏洞
影響：開發環境下的潛在 SSRF 攻擊
建議：運行 `bun update` 更新到安全版本
```

### 2. **CORS 配置** - 低風險
- 動態 CORS 源配置可能導致錯誤配置
- 建議明確設置允許的域而非依賴自動推導

### 3. **文件權限** - 低風險
- 設置文件創建時使用 `mode: 0o700`，但應驗證運行時權限
- 建議檢查 `~/.hapi/` 目錄的實際權限設置

### 4. **會話隔離** - 中等風險
- 單一用戶 ID (`getOrCreateOwnerId()`) 可能在多用戶場景下造成問題
- Telegram 用戶和 CLI 用戶共享相同的內部用戶 ID

## 🔒 **安全建議**

### 高優先級
1. **更新依賴**：
   ```bash
   bun update
   ```

2. **強化 CORS 配置**：
   ```typescript
   // 明確設置而非依賴自動推導
   corsOrigins: ['https://yourdomain.com']
   ```

3. **會話隔離改進**：
   - 為 Telegram 和 Web 用戶實施不同的用戶 ID 生成策略
   - 添加會話範圍權限檢查

### 中優先級
4. **加強令牌驗證**：
   ```typescript
   // 添加更嚴格的令牌格式驗證
   if (!token.match(/^[A-Za-z0-9_-]{40,}$/)) {
       throw new Error('Invalid token format');
   }
   ```

5. **日誌安全**：
   - 確保日誌文件不包含敏感信息
   - 實施日誌輪轉和清理策略

6. **文件權限檢查**：
   ```bash
   # 檢查並設置適當權限
   chmod 700 ~/.hapi/
   chmod 600 ~/.hapi/settings.json
   ```

### 低優先級
7. **速率限制**：為 API 端點添加速率限制中間件

8. **內容安全策略**：為 Web 應用添加 CSP 頭部

9. **安全頭部**：
   ```typescript
   app.use('*', (c, next) => {
       c.header('X-Content-Type-Options', 'nosniff')
       c.header('X-Frame-Options', 'DENY')
       c.header('X-XSS-Protection', '1; mode=block')
       return next()
   })
   ```

---

## 🎯 **總結**

HAPI 項目整體具有良好的安全基礎，特別是在密鑰管理和身份驗證方面。主要風險來自依賴漏洞和一些配置問題。

**建議優先處理：**
1. 更新 esbuild 依賴
2. 強化 CORS 配置
3. 改進會話隔離機制

這個項目可以安全重用，但建議在生產環境部署前實施上述安全建議。
